02Architecture

Three layers. The core is pure Swift and fully unit-testable with zero UI dependencies; surfaces are thin shells over the same engine and store.

Core (pure Swift)

TimerEngineState machine: idle → focus → shortBreak / longBreak, pause/resume/skip. Drift-free via wall-clock deadline, not tick accumulation. Publishes phase + remaining.
SessionStoreSwiftData: FocusSession lifecycle, daily aggregates, streak computation.
TicketRefParser: Jira key regex, GitHub URL / owner#123. Produces deep link + display badge.
CyclePresetWork/short/long durations, blocks-per-long-break, auto-advance flag.

Shell (AppKit glue)

SurfaceControllerOwns the one-surface-at-a-time state machine. Swaps popover / pinned panel / mini card. The trickiest code in the app.
StatusItemControllerNSStatusItem: icon reflects phase color, optional live countdown text.
FloatingPanelNSPanel subclass: non-activating, .floating level, joins all spaces, draggable.
AlertCenterUserNotifications + AVFoundation sounds, per-event toggles.

Surfaces (SwiftUI)

TimerViewHero digits, progress ring, session name + ticket, controls. Shared by all three surfaces.
SessionSetupViewName the block, paste a ticket ref, pick preset.
HistoryViewSessions by day, streak strip, completion counts. Momentum, not KPI tiles.
SettingsViewCycle presets, alerts, surface mode, launch at login.
CelebrationViewThe completion moment. Streak color, motion; instant under reduced-motion.

Surface exclusivity

Mode 1 · defaultMenu bar popover

Click the status item, popover opens, dismisses on click-outside. No other window exists.

Mode 2Pinned panel

Popover detaches into a non-activating panel anchored under the status item. Stays visible across apps and spaces until unpinned.

Mode 3Mini floating card

Compact frameless always-on-top card, draggable anywhere. Status item still works but only toggles the card.

invariant ⇒ exactly one surface mode active at any time
miniCard.visible ⇒ popover disabled ∧ pinnedPanel closed
pinnedPanel.open ⇒ miniCard hidden ∧ popover replaced by panel
mode switch ⇒ timer state untouched (engine outlives surfaces)

Data model

EntityFieldsNotes
FocusSessionname, ticketRaw, ticketKind (jira / github / none), startedAt, endedAt, plannedSeconds, completedBlocks, outcome (completed / abandoned)One row per named session, which may span multiple blocks

03Design system application

DESIGN.md is a seed; this build resolves it into real tokens. The rules that bind every UI agent:

RuleIn this app
State-Is-ColorFocus = warm ember (OKLCH ~68% 0.19 35). Break = cool teal. Streak/Reward = charged amber, completion only. The status item icon, progress ring, and neutrals all shift with phase.
Hero-DigitDigits are the largest element on every surface, tabular figures, heavy weight. In the mini card they ARE the card.
Earned-AccentAmber appears only in CelebrationView and the streak strip. Never ambient.
Flat-At-RestNo shadows while a block runs. Depth appears on hover, panel entry, and completion.
A11yWCAG AA contrast on all phase colors; prefers-reduced-motion (accessibilityReduceMotion) collapses celebration to a state change.

05Risks & open edges

  • Popover detachment. True NSPopover detachment is fiddly; the plan sidesteps it by rendering the pinned panel as its own NSPanel positioned under the status item rather than literally detaching the popover.
  • Menu bar countdown width. Live text next to the icon changes status item width every second; fixed-width tabular formatting avoids menu bar jitter.
  • Timer correctness through sleep. Mac sleeps mid-block: engine must reconcile against wall-clock deadline on wake, not resume ticking naively. Covered by TimerEngine tests.
  • SwiftData in a menu bar app. Fine unsandboxed for a personal build; the scaffold keeps the store path explicit so migration later is painless.
  • Headless verification limits. Menu bar UI can't be fully asserted from CLI; P3 compensates with a scripted launch + accessibility inspection + human eyeball pass at the end.
